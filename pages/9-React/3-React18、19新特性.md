# React18、19新特性

## React 18

### 1.并发渲染

- 渲染任务可**中断、暂停、恢复**，高优先级任务（用户输入）可以打断低优先级渲染（列表渲染、数据加载），解决大页面卡顿、输入延迟问题腾讯云开发...。
- 必须使用新根 API：`createRoot`，旧的`ReactDOM.render`废弃，不开启并发模式。

问：React16.8就支持hooks，为什么18才支持并发渲染？

# 澄清：React16.8 Fiber ≠ 已经开启并发渲染（Concurrent）

> 面试高频坑点，很多人混淆：**Fiber 是底层数据结构（地基），并发渲染是上层运行模式（房子）**稀土掘金。

## 1. React16 做了什么

React16 重构 **Fiber 协调器**，把递归栈改成链表遍历，具备**可暂停、可恢复、时间切片**的底层能力，这是并发渲染的**必要前提，但不是并发渲染本身**。

- ✅ 内部引擎：Fiber 链表、Scheduler 调度器、lanes 优先级机制已经写好了
- ❌ **默认是 Legacy（同步模式）**，`ReactDOM.render()` 入口，**渲染阶段依然是同步执行，不能被抢占中断**腾讯云开发...。
- 16/17 有一个**实验性的 Concurrent Mode**，需要手动开启，不推荐生产使用，有大量 bug，API 不稳定，官方后来废弃了这个全局模式腾讯云。

> 重点：React16 的 Fiber，**只能做到时间切片（把大任务切小块，让出主线程），但是没有 “高优先级更新抢占、抛弃低优先级渲染任务” 的并发能力**。 也就是说：**一旦开始一次更新，必须跑完整个 render 阶段，只是中间可以让出主线程，但是不能被别的更新打断**。

## 2. React18 的变化（真正落地并发渲染）

React18 不是重写 Fiber，而是**把 Fiber 底层能力正式开放出来，引入新根 API** `createRoot`，开启**并发渲染（Concurrent Rendering）**，这是真正的抢占式调度React。

### 核心区别（面试口述）

表格

| 维度             | React16/17 Legacy 模式（Fiber 引擎，但同步） | React18 createRoot（并发渲染）                                             |
| ---------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| 渲染阶段         | 一旦开始，**不能被中断**，必须完整跑完       | 渲染阶段可以被**高优先级任务抢占、放弃、重新做**                           |
| 任务调度         | 时间切片：分片执行，但任务不可被抢占         | 优先级调度：高优先级更新可以打断正在跑的低优先级渲染，丢弃旧的 render 结果 |
| 双缓冲 alternate | 存在，但只用于更新，不会丢弃渲染工作         | 可以丢弃正在构建的 workInProgress 树，重新渲染                             |
| 对外 API         | 没有 useTransition、useDeferredValue         | `useTransition`/`useDeferredValue`，标记高低优先级更新                     |
| 严格模式         | 不会双渲染                                   | 开发环境下，组件挂载‑卸载‑挂载，模拟并发下 render 多次执行                 |

> 关键概念区分：
>
> 1. **时间切片 Time‑slicing**：把长任务切成小块，让出主线程，**React16 就有**。
> 2. **并发渲染 Concurrent Rendering**：**可以中断、丢弃、重启渲染工作，高优先级抢占低优先级**，**React18 才正式可用**博客园。

### 为什么 16 有 Fiber 却不开放并发？

1. 并发渲染会带来：**render 阶段可能执行多次**，副作用不能写在 render 里；大量老项目的组件、第三方库不兼容。
2. 所以 React 团队选择：16‑17 只把 Fiber 底层做好，并发模式作为实验 API，不默认开启，避免大量业务崩掉。
3. React18 改成**渐进式并发**：不是全局开启开关，**只有调用 startTransition 等 API 才会触发并发特性**，旧代码行为保持兼容，不需要全部改造项目稀土掘金。

## 3. 面试高频追问回答模板

> Q：React16 已经重构 Fiber，为什么说 React18 才支持并发渲染？ A： Fiber 是底层数据结构，实现了可暂停恢复的时间切片，为并发打下基础。但是 React16 的默认 Legacy 模式下，**渲染阶段一旦启动就不能被抢占**，就算用 Fiber，整个更新任务还是要完整执行完毕。 并发渲染的核心是**高优先级更新可以打断、废弃正在进行的低优先级渲染工作**，这个能力在 React18 通过`createRoot`正式开放。 React16 虽然有实验 Concurrent Mode，但不稳定，生产不可用。React18 改成渐进式并发，通过`startTransition`等 API 选择性开启并发能力，兼容旧代码。

## 4. 补充小坑

- React18 如果仍然使用旧的`ReactDOM.render()`，依旧是 legacy 同步模式，**不会开启并发渲染**。必须使用`createRoot`。
- 并发渲染只作用于**render 阶段**；commit 阶段（真实 DOM 更新）永远同步不可中断

### 2.自动批处理 Auto Batching

- 以前：**只有事件处理函数内部**的 setState 会批量更新；`setTimeout、Promise回调`里面不会批量。
- React18：**所有场景自动批处理**，减少不必要重渲染；不需要手动`flushSync`做批处理React。

### 3. 新 Hooks

1. `useTransition`：标记非紧急更新，区分紧急（输入）和过渡更新（列表搜索、页面跳转），UI 不会阻塞。

```
const [isPending, startTransition] = useTransition();
startTransition(()=>{
  // 低优先级更新，不会阻塞输入
  setList(filterData);
})

```

1. `useDeferredValue`：延迟更新一个值，类似防抖，但由 React 调度，不是定时器；用于搜索结果、大列表渲染。

```
const deferredValue = useDeferredValue(inputValue);
// 用deferredValue去渲染大列表，输入不会卡顿

```

1. `useId`：生成稳定唯一 id，服务端 / 客户端 hydration 不冲突，用于表单 label、aria 属性。
2. `useSyncExternalStore`：用于外部状态库（redux、zustand），解决并发模式下订阅的坑。

### 4. Suspense 支持服务端流式 SSR

- 以前 Suspense 只在客户端；React18 支持服务端流式渲染，组件按需流式返回 HTML，不用等待全部数据加载完再返回页面，提升首屏体验React。

### 5. 严格模式 Strict Mode 双渲染

- 开发环境下组件会**挂载→卸载→再挂载**，模拟组件卸载重建，提前发现副作用没有清理的 bug。

### 6. 其它

- `Suspense`可以用于客户端数据获取（实验性）；
- 支持`startTransition`，可以在组件外调用。

## React19

### 1. React Compiler（React 编译器）【最大亮点】

> 自动记忆化，**不需要手动写 useMemo /useCallback/ React.memo**，编译器自动分析依赖，自动做缓存，减少重渲染。

- 不需要开发者手动维护记忆化，降低性能优化心智负担；
- 注意：编译器是可选开启，不是默认开启；**不会 100% 消除所有 useMemo**，复杂场景仍需要手动优化

### 2. Actions（表单动作）+ 新 Hooks

#### `useActionState`

处理表单提交，自动管理`isPending`加载状态、错误、表单状态；支持服务端 Action，原生表单渐进增强，无 JS 也可以运行。

```
const [state, submitAction, isPending] = useActionState(submitFn, initialState);
return <form action={submitAction}>
  <button disabled={isPending}>提交</button>
</form>

```

#### `useOptimistic` 乐观更新

在异步请求过程中，先展示预期结果；请求完成后自动回滚为真实数据。

> 例如：点赞，先 UI 显示点赞成功，接口返回失败再回退状态CSDN博...。

#### `useEffectEvent`

解决 useEffect 闭包捕获旧值问题，把事件函数稳定化，不需要把事件函数加入依赖数组。

### 3. React Server Components (RSC 服务组件) 稳定

- 服务端组件：**运行在服务端，不打包到客户端 JS**，可以直接访问数据库、文件系统，零客户端 bundle；
- 区分`'use client'`客户端组件，`'use server'`服务端 Action（服务端函数，可以被客户端调用）GitHub。

### 4. 原生支持 `use` Hook

可以直接在组件顶层 await Promise，配合 Suspense；**不可以在循环、条件内部使用**。

```
const data = use(fetchDataPromise);

```
