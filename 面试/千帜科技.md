## 面试题 & 标准答案

### 1. 怎么给 AI 数据脱敏

**题目**：把业务数据交给 AI（Cursor、Copilot、内部 Agent 等）时，怎么脱敏？

**答题结构**：先划敏感边界 → 再说脱敏手段 → 最后说工程落地与审计。

**（1）先定义什么要脱**

| 类型     | 例子                                            |
| -------- | ----------------------------------------------- |
| 身份标识 | 姓名、手机、身份证、邮箱、地址                  |
| 凭证密钥 | API Key、Token、密码、私钥、连接串              |
| 商业敏感 | 未公开财务、合同金额、客户名单、定价策略        |
| 内部信息 | 内网域名、员工工号、真实 traceId 关联的用户行为 |

原则：**能不进上下文就不进**；必须进时 **可逆性越低越好**（生产数据优先不可逆脱敏）。

**（2）脱敏手段（由轻到重）**

1. **规则/正则替换**：手机号 `138****1234`、身份证保留首尾、邮箱 `a***@domain.com`；适合结构化字段，实现快。
2. **分词 + NER**：用命名实体识别扫一遍再替换；适合日志、工单、自由文本。
3. **专用脱敏模型 / 私有化 Qwen**：比纯规则更懂上下文，适合非结构化长文本。
   - **专用模型**：PII 检测、实体识别、文本匿名化等垂直模型（或自训小模型），输入原文 → 输出已替换文本 + 实体类型标注；部署在内网，数据不出域。
   - **Qwen 系列**：通义千问可私有化部署（Qwen2.5 等），用 prompt / SFT 做「识别并替换手机、姓名、订单号」；也可只用其 NER 能力做前置扫描，再把脱敏结果交给 Cursor / GPT 等外部模型。
   - **典型链路**：`原始日志 → 内网 Qwen/脱敏模型 → 脱敏文本 → 公网大模型分析`；敏感识别与外传彻底拆开。
   - **选型**：格式固定、字段明确 → 规则优先；工单/聊天/堆栈混排 → 模型；合规要求高 → 必须内网模型，不外发原文。
4. **哈希/令牌化**：同一用户始终映射为 `USER_7f3a`，便于 AI 理解「同一人」但不暴露真值；密钥类只存哈希或干脆剔除。
5. **泛化/截断**：金额变区间、时间精确到日、日志只留错误栈框架去掉参数。
6. **合成/采样数据**：演示、写 Skill、跑 Agent 测试用假数据；与生产完全隔离。
7. **网关侧拦截**：在调用 LLM 前统一过一层 **脱敏中间件**（规则 + 专用模型/Qwen，IDE 插件、CI、MCP 代理均可），避免靠人肉记得改。

**（3）工程落地（面试可讲的闭环）**

```text
开发机 / CI / Agent
    → 敏感词库 + 正则（快路径）
    → 专用脱敏模型 / 内网 Qwen（慢路径，复杂文本）
    → 替换 / 阻断 / 告警
    → 仅脱敏后的上下文进外部大模型
    → 审计日志（谁、何时、脱敏前后 hash，不落明文）
```

- **本地 IDE**：`.cursorignore` / `.gitignore` 排除 `.env`、密钥文件；Rules 里写死「禁止把生产库连接串贴进对话」。
- **日志/报错给 AI 排查**：先跑脱敏脚本再粘贴；traceId 可保留，用户 ID 换成内部匿名 ID。
- **RAG / 知识库**：入库前批处理脱敏；检索结果二次过滤。
- **红线**：生产库直连 Agent、整表导出给公网模型 —— 一律不做；用只读沙箱 + 脱敏视图。

**可追问 & 答案**：

1. **脱敏和匿名化区别？** 脱敏是隐藏或替换具体值；匿名化强调无法关联回个人。给 AI 的日志通常要「可关联同一实体」时用令牌化，要「完全不可追溯」时用随机替换。
2. **AI 会把脱敏数据学走吗？** 取决于模型部署方式：公网 API 看厂商数据政策；企业私有化 / 不开训练的合约可降低风险。脱敏仍是第一道防线。
3. **怎么验证脱敏有效？** 用含已知敏感样本的测试集跑一遍，检查输出零泄漏；CI 里加 secret scanning（如 gitleaks）。
4. **为什么用 Qwen 而不是直接让 GPT 脱敏？** Qwen 可私有化，原文不出内网；脱敏与「推理分析」拆成两步，外网模型只见已清洗文本。专用小模型还可做低延迟、低成本批处理。

### 2. 怎么统一团队的 rules 等工具

**题目**：多人用 Cursor / AI 编程，怎么统一 Rules、Skills、Commands 等？

**答题结构**：单一事实来源 → 分层继承 → 版本与发布 → 落地习惯。

**（1）单一事实来源（放仓库）**

```text
repo/
  .cursor/
    rules/           # 项目级规则（命名、目录、禁改逻辑等）
  AGENTS.md          # 仓库级 Agent 说明（可选）
  .cursorignore
```

团队共识：**以 Git 为准**，个人 `~/.cursor` 只放主题等偏好，不放业务规则。

**（2）分层继承**

| 层级   | 内容                                         | 谁维护      |
| ------ | -------------------------------------------- | ----------- |
| 组织级 | 安全合规、禁止提交密钥、通用代码风格         | 平台/架构组 |
| 仓库级 | 技术栈、目录约定、业务名词                   | 项目负责人  |
| 目录级 | `pc-backend/*.mdc`、`miniapp/*.mdc` 按端拆分 | 各端 owner  |

子项目用 **glob 匹配** 的 `.mdc`，避免一条规则管全仓又臭又长。

**（3）Skills / Commands 统一**

- **Skills**：可复用工作流（发布检查、日志排查、OpenSpec 变更）写成 `SKILL.md`，放团队 Git 仓库统一维护，PR 合并后大家同步；用 tags（`frontend`、`mei`）方便检索。
- **Commands**：常用提示词模板 `/review`、`/openspec-new` 进仓库或组织插件，减少每人各写一套。
- **MCP**：统一维护团队 MCP 配置文档（哪些 server、哪些 env），敏感能力走内网网关，不散落个人机器。

**（4）发布与同步**

1. 规则变更走 **PR + Review**，像改 lint 配置一样严肃。
2. 大版本在 README 或 CHANGELOG 写「AI 协作变更说明」。
3. 新项目从 **模板仓库** 克隆，自带 `.cursor/rules`、基础 `SKILL.md`、`.cursorignore`；或从团队 skills 仓库复制/软链到 `.cursor/skills/`。
4. 定期 **distiller**：把踩坑对话沉淀成 rules/skills（面试可提 knowledge-distiller 思路）。

**（5）协作习惯**

- Code Review 顺带看「有没有把临时 prompt 写进 rules 污染全局」。
- Onboarding 清单：克隆 → 安装推荐 Skills → 读 `AGENTS.md` → 跑一条标准 Command。
- 禁止：每人本地一份「加强版 rules」不上库，导致 AI 行为不一致。

**可追问 & 答案**：

1. **和个人 Rules 冲突怎么办？** 项目 rules 优先；个人只保留与项目无关的偏好。
2. **规则太多模型不听？** 控制单条长度、按目录拆分；关键约束放文件靠前；重复的一条合并。
3. **怎么衡量统一效果？** 同类任务（如生成 API 层代码）多人产出结构一致；新人首日能靠文档跑通标准流程。

### 3. 概率题：两粒色子

**题目**：掷两粒色子，**至少一面朝上不为 5** 的概率是多少？（允许其中一面为 5）

**解法（补集）**：

- 总样本：\(6 \times 6 = 36\) 种等可能。
- 「至少一面不为 5」的反面 = **两面都是 5**，只有 \((5,5)\) 一种。
- \(P = 1 - \frac{1}{36} = \frac{35}{36}\)

**口算验证**：

- 第一粒为 5：第二粒有 5 种不为 5 → 5 种。
- 第一粒不为 5：第二粒任意 6 种都行，但其中「第一粒非 5 且第二粒为 5」已在「第一粒为 5」里算过第二粒非 5 的对称部分……用补集最不易错。

**答案**：\(\dfrac{35}{36}\)

## 复盘总结

| 薄弱项                            | 下次注意                                                               |
| --------------------------------- | ---------------------------------------------------------------------- |
| AI 脱敏若只讲「打星号」           | 补分层（规则 / 专用模型·Qwen / 令牌化 / 网关）、红线（生产直连）、审计 |
| 团队 rules 若只讲 `.cursor/rules` | 补 Skills/MCP 统一、PR 治理、模板仓库 onboarding                       |
| 概率题                            | 「至少一个」优先想补集；两骰子样本空间固定 36                          |

**岗位关联猜测**：偏 AI 工程化 / 内部提效（与叶子科技 PQA + Agent 方向类似），重点展示 **脱敏合规 + 团队 AI 工具治理** 的落地经验，而不仅是会用 Cursor。
