MySQL 是主流的关系型数据库，是数据最终一致性的保障。

1. 基础架构与存储引擎
   架构：MySQL分为Server层（连接器、分析器、优化器、执行器）和存储引擎层。

InnoDB vs. MyISAM：

InnoDB：默认引擎，支持事务、行级锁、外键，适合高并发写场景。

MyISAM：不支持事务，使用表级锁，适合读多写少的场景。

2. 索引
   数据结构：MySQL默认使用B+树索引。其特点是叶子节点存储数据且有序，非常适合范围查询。

索引类型：包括主键索引（聚簇索引）、二级索引（非聚簇索引）等。

优化策略：遵循最左前缀原则；尽量使用覆盖索引（索引已包含所需数据，避免回表）；利用EXPLAIN分析执行计划。

3. 事务与锁
   ACID：事务的四大特性：原子性、一致性、隔离性、持久性。

隔离级别：

读未提交 (RU)：可能脏读。

读已提交 (RC)：解决脏读。

可重复读 (RR)：MySQL默认级别，通过MVCC（多版本并发控制）解决不可重复读问题。

串行化 (Serializable)：最高级别，性能最低。

锁机制：InnoDB支持行级锁（共享锁S、排他锁X）和表级锁（意向锁）。

4. 日志系统
   Redo Log (重做日志)：InnoDB特有，用于保证事务的持久性。崩溃恢复时，重放Redo Log恢复已提交的数据。

Binlog (归档日志)：Server层的日志，记录所有逻辑操作，用于主从复制和数据恢复。

5. 高可用与扩展
   主从复制与读写分离：利用Binlog进行主从数据同步。将写操作指向主库，读操作指向从库，提升系统吞吐量。

分库分表：当单表数据量巨大时，将数据拆分到多个数据库或表中。这是解决大数据量、高并发写入的终极方案。

6. SQL 性能优化
   避免 SELECT \*：只查询需要的字段。

利用索引：确保WHERE和JOIN的字段有索引。

分析慢查询：开启慢查询日志，定位并优化慢SQL。

调整参数：如合理设置innodb_buffer_pool_size（通常为物理内存的50%-70%）
