1. 核心数据结构
   Redis支持多种数据结构，每种都有其独特用途。

String (字符串)：最基础的类型。常用于缓存、计数器、分布式锁。

Hash (哈希)：适合存储对象的属性（如用户信息）。

List (列表)：有序列表。可用于实现消息队列。

Set (集合)：无序且元素唯一。可用于标签、共同关注等场景。

Sorted Set (ZSet)：带分数的有序集合。是实现排行榜、延迟队列的利器。

高级数据结构：如用于UV统计的HyperLogLog、地理位置计算的GeoHash等。

2. 高性能与线程模型
   基于内存：数据存储在内存中，读写速度微秒级。

单线程模型：Redis核心网络请求处理是单线程的。这避免了多线程的上下文切换和竞争开销。

I/O多路复用：单线程配合非阻塞I/O多路复用技术，高效处理海量连接。

3. 持久化机制
   Redis提供两种持久化方式，防止数据丢失。

RDB (快照)：在指定时间间隔生成数据快照。适合备份，但可能丢失最后一次快照后的数据。

AOF (追加文件)：记录每个写操作命令。数据安全性更高，但文件体积可能较大。

混合持久化：Redis 4.0+支持，结合RDB和AOF的优点。

4. 内存管理
   过期策略：采用惰性删除（访问时检查） + 定期删除（周期性抽查）的组合策略。

淘汰策略：内存不足时触发，常用的有 allkeys-lru（最近最少使用）和 volatile-lru（针对有过期时间的key）。

5. 高可用与集群
   主从复制 (Master-Slave)：数据从主库同步到从库，实现读写分离和数据冗余。

哨兵模式 (Sentinel)：在主从基础上增加哨兵节点，监控主节点并在其故障时自动故障转移，实现高可用。

Cluster 集群：真正的分布式方案，通过哈希槽（16384个）将数据分片到多个主节点，解决了海量数据存储和高并发写入问题。

6. 常见问题与解决方案
   缓存穿透：查询不存在的数据。解决方案：布隆过滤器或缓存空对象。

缓存击穿：热点key过期，大量请求直达DB。解决方案：互斥锁（如分布式锁）。

缓存雪崩：大量key同时过期。解决方案：设置不同的过期时间（如添加随机值）。

7. 分布式锁
   利用Redis的原子性操作实现分布式环境下的资源互斥。

实现：通常使用 SET key value NX EX seconds 命令。

挑战：需处理好锁的超时、释放（用Lua脚本保证原子性）等问题。Redisson等客户端提供了更完善的封装。
