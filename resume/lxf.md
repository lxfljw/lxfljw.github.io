### **1、工程化：Yarn 迁移 pnpm 与 Node 升级** <span class="time">有赞科技 · 2024.06 - 至今</span>

**项目说明**：日常以业务需求与 Java 侧功能开发为主；本项为并行推进的**前端工程化专项**，改善大仓依赖与构建稳定性，减少与业务发版无关的阻塞。

**项目描述**：将仓库与工作流从 Yarn 迁移至 pnpm，并推进 Node 版本升级；通过 pnpmfile 编写兼容逻辑，缓解依赖解析与旧包不兼容问题。

**业务价值**：降低多仓库/多包场景下的安装与 CI 不稳定，减少因依赖与 Node 版本不一致导致的**发版阻塞**，让业务需求能按节奏合并与上线。

**项目职责**：负责 Yarn 向 pnpm 的迁移与 Node 升级落地；编写并维护 pnpmfile，处理依赖兼容问题，协助对齐本地与 CI 的安装与构建表现。

**技术要点**：
- 迁移包管理器：Yarn → pnpm，调整安装脚本、CI 与锁文件策略
- 升级 Node 版本，配合本地与流水线环境对齐
- 使用 pnpmfile（如 `readPackage` 等钩子）做依赖兼容与解析层适配，降低升级阻力

<br>

### **2、零售系统升级和重构** <span class="time">兔展科技 · 2023.01 - 2023.07</span>

**项目背景**：系统约 90% 页面基于 Vue 1，Webpack 1.x 构建慢、生态陈旧，本地 HMR 约 8 秒，严重拖累效率。

**项目描述**：升级 Web 与小程序技术栈，接入 TypeScript、Element Plus、Tailwind CSS，重构核心「装修」模块。

**业务价值**：零售与营销侧页面、活动落地页及小程序端需**高频改稿与上线**；升级后缩短需求从开发到联调、提测的等待时间，降低老栈带来的迭代与招聘/协作成本。

**项目职责**：主导升级至 Vue 3，完成 Vue Router 与权限路由兼容；接入 pnpm 加速依赖安装；升级 Webpack 5 并兼容 Vite；集成 TS、Element Plus、Tailwind、ESLint 等，改善开发与构建体验。

**技术要点**：
- Vue 3 语法与生态迁移，升级 vue-loader，全量从 JS 拥抱 TypeScript
- Webpack 5 集成 swc、thread-loader 加速构建，同时兼容 Vite，支持体积与耗时分析
- 编写脚本将 js/html 合并为 `.vue` 并做语法替换，合并工作量约减少 80%

**项目成果**：
- Vue 3 生态落地后，整体开发效率约提升 20%（含构建与联调等待缩短、同类需求交付周期体感等综合复盘）
- 首页装修系统重构，代码复用率提高，单文件由约 2000 行降至平均约 330 行，**装修类需求**扩展与改版成本明显下降
- Vite 本地构建速度提升约 90%，Webpack 生产构建速度提升约 36%
- 路由采用适配器模式升级，路由与权限相关改动量减少约 90%

### **3、前端埋点架构设计** <span class="time">兔展科技 · 2022.04 - 2022.10</span>

**项目背景**：各项目埋点方案不统一，部分实现侵入业务逻辑，需统一架构。

**项目描述**：基于 React 设计自动化埋点体系，通过配置生成埋点，减少手写代码。

**业务价值**：为运营、活动与增长分析提供**口径统一、可复用**的采集能力（点击/曝光/路由），支撑后续漏斗与页面级效果评估，减少「埋点扯皮」占用的排期。

**项目职责**：技术选型、开发、测试、文档与部署；设计并实现自动化埋点架构；导出曝光埋点组件；维护前端脚手架模板。

**技术要点**：

Web 端：
- 重写 history 路由监听，结合路由配置做匹配与上报
- 拦截 `createElement` 与 `onClick`，依据元素绑定数据上报
- 导出曝光组件，基于 IntersectionObserver 检测可见性，支持延时上报等配置

小程序端：
- 代理 `Page` / `Component`，在生命周期内自动上报
- 拦截点击回调，按元素绑定数据上报
- 实现通用曝光埋点组件

<br>

**项目成果**：
- 统一埋点方案，减少埋点代码量与维护成本，开发效率约提升 20%
- 点击与曝光低侵入，对业务逻辑影响可控
- 脚手架模板可快速接入埋点能力，新业务/新活动页可更快进入数据采集与复盘

**项目背景**：团队规范分散于文档，缺乏工程化落地载体；新项目需人工逐一接入监控、Lint、CI 等，重复劳动多且一致性差。

**项目描述**：设计并实现一套面向团队的前端工程化脚手架平台，覆盖项目初始化、子命令能力、远程模板与版本管理及一键启动，将团队规范内聚为可执行的工程能力。

**业务价值**：把「能上线、可监控、可维护」前移到**项目创建第一天**，缩短从需求立项到可开发、可联调的时间，让业务项目更快进入交付轨道。

**项目职责**：主导架构设计与技术选型，完成核心 CLI、各子命令与远程模板管理、文档发布；设计交互式创建流程，降低使用门槛。

**技术要点**：
- 交互式 CLI，策略模式组织子命令，便于扩展与维护
- 远程模板与配置统一管理，按需拉取；创建流程中可选接入监控、Lint、CI 等预设能力
- 模板与 CLI 解耦、版本化管理，弱网与重复创建场景下复用本地缓存，缩短初始化等待

**项目成果**：
- 新项目从创建到本地运行耗时从约 2 小时压缩至 10 分钟内，启动效率提升约 90%
- 规范接入由人工对照文档改为命令一键完成，一致性与可追溯性显著提升
- 降低新人上手门槛，成为团队标准工程底座，累计支撑数十个项目初始化

### **5、小程序构建发布与协作系统** <span class="time">兔展科技 · 2020.12 - 2021.04</span>

**项目背景**：小程序调试周期长，手动上传与版本号维护易冲突；多人协作存在覆盖风险，需要从零散脚本沉淀为**可复用的端到端能力**。

**项目描述**：搭建一套面向团队的小程序**构建—上传—分发**系统：以配置驱动 CLI 为统一入口，串联构建、多模板上传、预览与检查；版本号与发布动作集中管理，关键步骤失败自动重试；配套**取码平台**聚合预览码与体验码，让研发、测试与业务侧在同一套流程里协作。

**业务价值**：营销/活动类小程序发版频繁，系统落地后**缩短提审前准备与联调反馈周期**，降低版本覆盖风险；取码路径标准化，减少口头传码与反复打包，业务侧更快拿到可体验的预览与体验版。

**项目职责**：负责方案设计与核心实现：技术选型，CLI 与测试脚本、上传/预览/检查/版本与重试链路，以及取码平台搭建与使用说明。

**系统能力**：
- **发布链路**：配置化驱动构建与上传，支持多模板并行；预览与检查纳入同一套命令流程，失败可重试
- **版本与协作**：版本号与发布记录统一管理，缓解多人并行时的冲突与误覆盖
- **分发与协作**：取码平台统一输出预览码/体验码，服务联调、验收与企业微信等场景

**项目成果**：
- 构建与发布流程自动化，开发效率约提升 15%
- 版本号与协作冲突问题缓解，协作效率约提升 60%
- 取码平台提升联调与企业微信侧开发效率约 30%
